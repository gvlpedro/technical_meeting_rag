Meeting transcripts → living architecture

Architecture evolution RAG

De transcripciones de reuniones a una arquitectura viva, versionada y consultable por chat.

El problema

Las decisiones de arquitectura se hablan… y se pierden

  • Una reunión decide cambiar un contrato de datos, pero el porqué se queda en el audio
  • Seis meses después nadie sabe si ese campo era opcional desde el principio
  • El único "registro" real es la memoria de quien estaba en la sala
La idea

Cada reunión se convierte en un registro permanente

  • Subes la transcripción → el sistema genera un ADR (Architecture Decision Record)
  • Cada componente y cada contrato de datos queda versionado, nunca sobreescrito
  • El historial completo — no solo el estado actual — queda consultable
El resultado

Un chat que conoce toda la evolución, no solo el presente

"¿Cómo era este contrato en la versión 1?" tiene una respuesta exacta — anclada a la fila real de esa versión, no inventada.

Generación del ADR

El sistema se corrige antes de preguntarte

  • Actor — redacta un primer borrador del ADR
  • Crítico — señala huecos o ambigüedades reales
  • Jefe — decide qué se infiere y qué te pregunta a ti
El modelo de datos

Gold: un historial que nunca se sobreescribe

Cada componente o contrato se compara con su última versión — new · modified · unchanged · removed — y cada cambio real queda como una fila nueva, nunca como una edición.

Consulta

El chat no solo recupera — verifica

Verificación de citas

Cada afirmación se contrasta contra la fila real de Gold antes de entregarse.

Corrective RAG

Si la primera recuperación no es suficiente, el sistema reformula y vuelve a buscar.

Expansión de consultas

Una pregunta ambigua se amplía para cubrir sinónimos y entidades relacionadas.
